4.3 Coding Format 
Request and response packets use the JSON format. 
4.4 URI Format 
NBI APIs are designed based on the REST Architecture. 
The RESTful URI of resources use the following format: 
https://ip:port/{context-path}/{rest-path} 
 
Element 
Description 
ip:port 
NBI service interface IP and port 
context-path 
Context-path (such as cpi,jeep,etc.. ) 
rest-path 
Resource path (such as devices, auth, etc...) 
4.5 Request Methods 
Operations performed on the IoT platform resources shall comply with the HTTP methods. 
The operations performed can be classified into: create, retrieve, update and delete 
(CRUD) as described below: 
Method 
Resource Operation 
GET 
Obtaining resources 
POST 
Creating resources

4.6 Response Codes 
Each IoT platform NBI request shall be associated with a response status code. 
Some of the response status codes along with the description is listed below: 
Status Code 
Description 
200 OK 
A request is successfully received, and the request response header or 
data body will be sent in the response. 
201 Created 
The POST or PUT operation is successful. 
204 No Content 
The server has successfully fulfilled the request and that there is no

The server cannot or will not process the request due to an apparent 
client error (e.g., malformed request syntax, invalid request message 
framing, or deceptive request routing). 
401 Unauthorized 
Similar to 403 Forbidden, but specifically for use when authentication 
is required and has failed or has not yet been provided. 
403 Forbidden 
The request was a valid request, but the server is refusing to respond 
to it. 403 error semantically means "unauthorized", i.e. the user does 
not have the necessary permissions for the resource. If the cause 
cannot be disclosed, 404 Not Found is returned. 
404 Not Found 
The server has not found anything matching the Request-URI. 
405 Method Not Allowed 
The method specified in the Request-Line is not allowed for the 
resource identified by the Request-URI. 
409 Conflict 
The request could not be processed because of conflict in the request, 
such as an edit conflict between multiple simultaneous updates. 
414 Request-URI Too Long 
The URL can contain a maximum of 2083 characters. 
429 Too Many Requests 
The user has sent too many requests in a given amount of time. 
500 Internal Server Error 
A generic error message, given when an unexpected condition was 
encountered and no more specific message is suitable.
