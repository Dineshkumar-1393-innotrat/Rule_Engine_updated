6.2 MQTT 
MQTT shall be the protocol interface between the CVIP and Dongle. The scalable and enterprise 
grade MQTT broker  used on the CVIP currently supports only MQTT v3.1.1.  
QoS level-1 shall be used for the MQTT publish/subscribe requests for all topics. Use of QoS 
level-2 will not be evaluated as it involves overheads and needs to be prototypes and performance 
benchmarked.

6.2.4 MQTT Keep Alive  
The clients connecting to MQTT broker in CVIP are expected to configure the keep alive time of 
10 minutes. This means that the client is expected to publish at least one message within 10 minutes 
from the last communicated message. If there is no communication of message for the past 10 
mins, then the client is expected to publish a PingReq message. 
 
The MQTT broker shall wait for 15 minutes ( 1.5 times the keep alive timer) to abort a MQTT 
session if there is no communication from the client.

7.2.1.1 Assumptions 
• First eight digits of the IMEI is the TAC value which is uniquely allocated for Dongle

Manufacturer.

manufacturer and then updated  in the next version of the document.

7.2.6 Vehicle Discovery  
• When Dongle is fitted in the vehicle and VIN is provisioned, then Dongle state changes 
from factory to provisioned state. 
• When turned on, Dongle sends Vehicle discovery with payload as detailed in section 
Message format for topic “/dongle/{{vinnum}/{protocol}{data format}/deviceJoined” 
from Dongle to CVIP. 
• CVIP, on successful validation of the payload communicates the device joined response 
and dongle state change from PROVISIONED to AUTHORIZED is triggered to dongle. 
• Upon receiving the successful dongle state update command response CVIP updates the 
respective dongle state to AUTHORIZED.

# SB API Interface ID : SB-FOTA_COMMANDS-004 
NOTE: The firmware types will be determined after discussion with DONGLE

After firmware download command is triggered from CVIP, Dongle acknowledges the FOTA 
command with a response. In case the FOTA command was received in IGN ON, DONGLE will 
save it and start update/install in IGN OFF. In IGN OFF, DONGLE start update/install procedure 
after trip end(2h). 
 
If Dongle is in Authorized state, the following requirements shall be considered. 
• If IGN OFF, DONGLE cannot receive the FOTA command because DONGLE is in deep 
sleep mode. 
• If IGN ON, DONGLE can receive the FOTA command. 
• If IGN changed to ON from OFF while FOTA in progress, DONGLE keeps the FOTA 
progress without stop.

The command includes the following parameter, which is explained in detail. 
 
• Command ID or message_id 
This UUID is supposed to be passed as an input parameter during the download request 
while hitting the URL. Also, this parameter is supposed to be communicated as FOTAID 
as part of device joined post device reboot after FOTA installation. 
• firmwareType 
This parameter specifies if the package is applicable for MCU or NAD 
• URL 
The download URL which needs to be accessed by the Dongle to initiate the download. 
• accessToken 
Authentication token which needs to be passed as authorization header during download 
initiation. This token is valid for a maximum duration of 7 days. 
• rawCheckSum 
SHA-256 checksum of the FOTA package to validate the hash values of FOTA package 
• SoftwareSize 
Size of the FOTA package in bytes.

14. Vehicle Alerts & Events  
# SB API Interface ID : SB-ALERTS_EVENTS-001 
Alerts and Events are to be processed real-time; hence it has to be sent as decoded value (not as 
CAN frames) to CVIP.

• Vehicle Event 
• Vehicle Alerts  
• Emergency & Safety Alerts 
• Diagnostic Alerts 
• Driving Score
